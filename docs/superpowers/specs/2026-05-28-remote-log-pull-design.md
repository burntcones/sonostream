# Remote Log Pull (on-demand) — Design

**Date:** 2026-05-28
**Status:** Approved (pending spec review)
**Component of:** Aux (sonostream-android) + a new standalone Vercel relay

## Problem

Debug dumps (`/api/debug`) can only be pulled on the cafe LAN today — long-press
the Aux logo → Share, or `curl http://<tablet-ip>:8077/api/debug` from a device on
the same WiFi. Diagnosing intermittent failures at a cafe (e.g. IOI's silent-stop)
therefore requires someone physically present on the cafe network. We want to pull a
tablet's dump remotely.

The tablet sits behind the cafe router (no public IP, NAT), so it cannot be reached
*inbound*. It does have *outbound* internet (OTA already fetches `update.json` + APKs
from GitHub, routing over a validated network when cafe WiFi lacks internet). The
design therefore is **tablet-initiated push**, triggered by a flag the tablet polls.

A hard constraint: the APK ships via **public** GitHub releases, so **no secret may
live in the APK** — anyone can extract it. This rules out embedding tokens or
writable URLs whose possession grants trust.

## Goals

- Pull any cafe's latest `/api/debug` dump remotely, on demand.
- No secret in the APK.
- No impact on playback (best-effort, isolated from the Sonos path).
- Minimal infra the dev deploys once and forgets.

## Non-Goals (YAGNI)

- Continuous/periodic telemetry (explicitly chose on-demand pull).
- Admin web UI (curl one-liners suffice for v1; a page can come later).
- HMAC-signed uploads (nonce-gating matches the threat level).
- Dump history (store only the latest dump per device).

## Decisions (locked)

| Fork | Decision |
|---|---|
| Trigger | On-demand pull — tablet polls a flag, uploads when set |
| Destination | A tiny Vercel relay (one function + Vercel KV) that hosts **both** the flag and the dump |
| Device key | First discovered Sonos room name (e.g. `IOI`), fallback `tablet-<android_id_prefix>` |

## Architecture

Two deployables:

1. **Relay** — a standalone minimal Node/TypeScript Vercel project (its own repo, e.g.
   `sonostream-relay`). The Android repo is not a Node project, so the relay does not
   live inside it. Uses Vercel KV (Upstash, free tier) for state.
2. **Android poller** — a new `RemoteCommandPoller.kt` started by `StreamerService`,
   reusing `UpdateChecker`'s internet-capable-network selection.

### Flow

```
Dev                         Relay (Vercel + KV)                 Tablet (cafe)
 │  POST /api/cmd?device=IOI  │                                   │
 │  x-admin-token: <secret>   │                                   │
 │ ─────────────────────────► │ cmd:IOI = <random nonce>          │
 │                            │                                   │
 │                            │ ◄──── GET /api/cmd?device=IOI ──── │  (poll ~90s)
 │                            │ ────► {requestId: <nonce>} ──────► │
 │                            │                                   │ nonce != lastHandled?
 │                            │ ◄─ POST /api/logs?device=IOI ───── │  body: {requestId, dump, ts}
 │                            │    (nonce must match cmd:IOI)      │
 │                            │ log:IOI = {...}; clear cmd:IOI     │
 │                            │ ────► 200 ──────────────────────► │ lastHandled = nonce
 │  GET /api/logs?device=IOI  │                                   │
 │  x-admin-token: <secret>   │                                   │
 │ ─────────────────────────► │ ────► {receivedAt, requestId,     │
 │                            │        dump} ───────────────────► │  (dev reads)
```

Latency between requesting and receiving a dump is ≤ one poll interval (~90 s) plus
upload time. Acceptable for debugging.

## Relay API contract

Base URL (hardcoded in the app; not a secret): `https://<project>.vercel.app`

| Method | Path | Auth | Purpose | Response |
|---|---|---|---|---|
| `POST` | `/api/cmd?device=<key>` | admin | Set fresh nonce (request logs) | `{requestId}` |
| `GET`  | `/api/cmd?device=<key>` | public | Tablet polls pending request | `{requestId}` (`""` when none) |
| `POST` | `/api/logs?device=<key>` | nonce | Tablet uploads dump | `200` / `409` if nonce mismatch |
| `GET`  | `/api/logs?device=<key>` | admin | Dev reads latest dump | `{receivedAt, requestId, dump}` or `404` |

- **Admin auth:** header `x-admin-token` compared against Vercel env `ADMIN_TOKEN`.
  Lives only in Vercel env + the dev's shell. Never in the APK.
- **Nonce auth (`POST /api/logs`):** request body must include `requestId` equal to the
  current `cmd:<device>` value. On match: store `log:<device>`, delete `cmd:<device>`,
  return 200. On mismatch/empty: 409, store nothing.
- **Nonce:** `crypto.randomUUID()` generated by the relay on `POST /api/cmd`.

### KV keys

- `cmd:<device>` → string nonce (absent/empty = no pending request)
- `log:<device>` → JSON `{ receivedAt: <iso>, requestId: <nonce>, dump: <object> }`

Dump size ~100–300 KB; well within KV value limits.

### Convenience one-liners (documented for the dev)

```bash
# Request logs from IOI
curl -X POST "https://<project>.vercel.app/api/cmd?device=IOI" -H "x-admin-token: $AUX_ADMIN"
# Read the latest dump (after the tablet's next poll, ~90s)
curl "https://<project>.vercel.app/api/logs?device=IOI" -H "x-admin-token: $AUX_ADMIN" | jq .dump
```

## Android component: `RemoteCommandPoller`

- **Lifecycle:** started by `StreamerService.onCreate`, stopped in `onDestroy`. Daemon
  thread loop, ~90 s cadence, under the existing foreground-service wake lock.
- **Network:** routes over a validated internet network like OTA. `UpdateChecker`'s
  `openConnection(url, context)` / `findInternetNetwork(context)` are currently private;
  expose them (make `internal`) or extract a shared `NetworkUtil` helper so the poller
  reuses the exact same path. (Implementation detail for the plan.)
- **Device key derivation** (pure, unit-testable):
  ```
  deviceKey = SonosManager.speakers.values.map { it.name }.sorted().firstOrNull()
              ?: "tablet-" + androidId.take(6)
  ```
  URL-encode before use. Deterministic for multi-speaker tablets (sorted + first).
- **Upload decision** (pure, unit-testable): `shouldUpload(fetchedNonce, lastHandled) =
  fetchedNonce.isNotEmpty() && fetchedNonce != lastHandled`.
- **Dump source:** GET the local `http://127.0.0.1:8077/api/debug` over loopback (the
  server is already running) to reuse the exact dump the panel/Share produce. Loopback
  needs the default network, not the internet network — keep the two connections
  distinct.
- **Dedupe state:** `lastHandledRequestId` in SharedPreferences. Set **only** after the
  upload POST returns 200, so a failed upload retries on the next poll. Belt-and-
  suspenders with the relay clearing the nonce on success.
- **Config:** relay base URL as a `const`/`var` on the poller (like
  `UpdateChecker.manifestUrl`). Not a secret.

## Security model

| Surface | Exposure | Mitigation |
|---|---|---|
| Relay base URL in APK | Public | It's just a URL; no trust attached to possession |
| `GET /api/cmd` | Public read | Returns only a random nonce — leaks nothing |
| `POST /api/logs` | URL public | Requires current single-use nonce; junk → 409. Worst case: someone watching the public nonce uploads one dump for a device before the tablet — low stakes, consumed immediately |
| `GET /api/logs`, `POST /api/cmd` | Admin-gated | `x-admin-token`; cafe data (local IPs, file names, UUIDs) not world-readable |

The admin token is the only secret and never ships in the APK.

## Error handling

- All network ops wrapped in try/catch; failures log and the loop continues.
- Endpoint down / no internet → next poll retries; zero playback impact.
- Loopback `/api/debug` failure → skip this cycle, retry next poll.
- Nothing in this feature touches `SonosManager`, the audio path, or the
  `PlaybackMonitor`.

## Testing

- **Relay:** `vercel dev` + curl scripts covering: set nonce → poll returns it →
  upload with right nonce (200, nonce cleared) → upload with wrong/empty nonce (409) →
  admin reads dump → admin endpoints reject missing/wrong token. Unit-test the
  nonce-gating handler.
- **Android:** unit-test the two pure functions (`deviceKey` derivation,
  `shouldUpload`). Network/loopback paths verified manually on a tablet (set flag via
  curl, confirm dump lands).

## Rollout

- Ships in the next app version (≥ 2.3.13) via the existing OTA workflow.
- Relay deployed first so the polling target exists before tablets update.
- `ADMIN_TOKEN` set as a Vercel env var; dev keeps it in their shell (`$AUX_ADMIN`).

## Future (out of scope now)

- Admin web page (device list, "request logs" buttons, dump viewer).
- HMAC-signed uploads if abuse ever appears.
- Optional `requestId=heartbeat` mode to also fetch the rolling heartbeat history.
